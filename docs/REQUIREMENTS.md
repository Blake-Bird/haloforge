# HaloForge acceptance ledger

The full user objective is preserved in OBJECTIVE.md. This ledger tracks every list item; paragraphs and examples in the objective remain binding context. No item is complete merely because a related test passes. External reviews, adoption, and measured learning outcomes require external evidence.

## Status semantics

This is a deliberately conservative acceptance ledger, not a feature inventory. `Open` means that this individual requirement has not been accepted with requirement-specific evidence in this table; it does **not** mean that no related implementation exists. Consult [IMPLEMENTATION-STATUS.md](IMPLEMENTATION-STATUS.md), [KNOWN-LIMITATIONS.md](KNOWN-LIMITATIONS.md), and [REPOSITORY-REVIEW.md](REPOSITORY-REVIEW.md) for current implemented work, known boundaries, and independently unverified claims. A requirement should move out of `Open` only when its row gains direct, durable evidence—not because a broadly related test happens to pass.
